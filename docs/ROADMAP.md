# 개발 범위와 다음 단계

## 현재 완료 범위

- 인증과 사용자 컨텍스트
- 워크스페이스 생성·조회·멤버 목록·소프트 삭제
- 워크스페이스별 개인 근무 컨텍스트 예외
- Slack형 1:1 DM 목록
- 메시지 조회와 전송
- 읽음 상태
- 사용자별 현지 시각 표현

## 와이어프레임 확정 후 결정할 항목

1. 메시지 수신 갱신을 폴링으로 유지할지 WebSocket/STOMP 또는 SSE로 전환할지
2. 채널 UI가 필요해지는 경우 `DIRECT` 외 `CHANNEL` 대화 타입과 역할/권한 추가
3. 메시지 수정·삭제·답글·리액션 중 실제 화면에 들어갈 기능
4. 사용자 상태, 프로필 이미지, 최근 접속 시각의 필요 여부
5. AI 검토가 전송 전 초안에 붙는지, 전송된 메시지에 별도 액션으로 붙는지

## AI 워크플로우 확정 후 추가할 도메인 후보

- `ai_analyses`: 원문 분석 요청과 구조화 결과
- `understanding_cards`: 사용자가 확정한 업무 조건
- `card_revisions`: 조건 변경 버전
- `recipient_responses`: 수신자의 확인·기한 조정·불명확 응답
- `agreement_logs`: 최종 합의 이력

AI 도메인은 현재의 `messages.id`를 참조하도록 추가하되, 원문 메시지를 수정하거나 전송을 막는 구조로 만들지 않는 것을 권장합니다.
